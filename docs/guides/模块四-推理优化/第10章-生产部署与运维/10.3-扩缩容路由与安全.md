## 主线材料

[vLLM Production Stack 介绍](https://vllm.ai/blog/2025-01-21-stack-release) 用 prefix-aware routing 与 autoscaling 说明组件关系。它没有完整覆盖联合信号与 API 安全，本页补齐这两部分。

## 为什么不能只看 GPU 利用率

LLM worker 加载慢，KV 与 prefix 有局部性，GPU utilization 又会因 Prefill/Decode 波动。扩缩容至少结合 waiting tokens、预计排队时间、TTFT/TPOT SLO、KV 水位和近期到达率。

~~~mermaid
flowchart LR
    M["队列 + token + SLO 指标"] --> SCALE["扩缩容决策"]
    SCALE --> WARM["新副本加载与预热"]
    WARM --> READY["readiness 通过"]
    READY --> ROUTE["路由逐步分流"]
    ROUTE --> LOCAL["兼顾 prefix / adapter locality"]
~~~

缩容前先停止新流量，等待活跃请求与 KV 状态清理。直接删除最空闲 Pod 也可能丢掉高价值 Prefix Cache 或热点 Adapter。

## 路由目标

在满足 SLO 前提下，综合队列 token、KV 可用空间、prefix/Adapter 命中、请求优先级和实例健康。Prefix 命中不能凌驾于排队时间，否则热点前缀会把单实例压垮。

## 安全边界

- 认证、授权、租户配额与管理接口隔离；
- prompt、输出、日志和 trace 脱敏；
- 模型、Adapter、自定义代码与镜像供应链验证；
- URL/文件/工具调用的 allowlist、大小、超时与沙箱；
- 限制 max tokens、并发、请求率和 body 大小；
- 错误信息不暴露内部路径、密钥和其他租户状态。
