## 主教程

先读 [vLLM Kubernetes Production Stack 介绍](https://vllm.ai/blog/2025-01-21-stack-release) 理解组件关系，再到 [Production Stack 仓库](https://github.com/vllm-project/production-stack) 跟随固定 release 部署。Kubernetes GPU 与探针文档只用于核对配置。

## 镜像与模型

镜像应锁 digest，并记录 CUDA runtime、vLLM、PyTorch 与系统依赖。宿主机 driver 必须与容器 CUDA 兼容。模型 revision、tokenizer、chat template、量化文件与自定义代码需要独立锁定，不能只写一个可漂移的模型名。

模型可烘焙进镜像、挂载共享存储或启动时下载。三者分别影响镜像大小、冷启动时间、存储带宽和供应链验证。无论哪种方式，都应校验文件哈希并限制远程代码执行。

## GPU Pod 的关键边界

- 请求整数 GPU 资源，并用 node selector/affinity 约束目标型号；
- 多 GPU Pod 验证设备拓扑，不假设编号连续就有 NVLink；
- 为 /dev/shm、主机内存和临时盘留足空间；
- TP/PP worker 的 placement 与 Pod 拓扑一致；
- 模型加载完成前不接流量。

## 三种探针

startup probe 覆盖模型下载、加载和预热；readiness probe 决定是否接收新流量；liveness probe 只判断进程是否无法恢复。把模型加载慢误判为 liveness 失败会造成重启循环。

优雅终止顺序是先让 readiness 失败并停止接新请求，再等待或取消存量请求，最后释放 worker。终止宽限时间必须覆盖最长允许请求或明确的强制取消策略。
