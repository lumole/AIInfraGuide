## 灰度主教程

[KServe Canary Rollout Tutorial](https://github.com/kserve/website/blob/71c8b22a05d6be72560b2cc326865930063cd0e8/docs/model-serving/generative-inference/llmisvc/canary-rollout.md) 按 stable/canary、流量权重、观测窗口和回滚逐步展开，适合跟着练习。它没有覆盖 LLM 特有事故，本页补齐这部分。

## 发布前

- 固定模型、tokenizer、模板、引擎和镜像 revision；
- 完成离线质量集、协议、性能和资源门禁；
- 准备兼容的前一版本与一键回滚；
- 定义灰度每阶段流量、观察时间和停止阈值；
- 确认新旧版本的 KV/会话状态不能错误混用。

## 灰度过程

~~~mermaid
flowchart LR
    OFF["离线回放"] --> S1["1%"]
    S1 --> S10["10%"]
    S10 --> S50["50%"]
    S50 --> FULL["100%"]
    S1 -.失败.-> RB["停止扩流并回滚"]
    S10 -.失败.-> RB
    S50 -.失败.-> RB
~~~

每阶段同时比较质量、TTFT/TPOT p99、错误率、OOM、goodput 和成本。只比较平均延迟不足以发现队列或长上下文回归。

## LLM 事故 Runbook

### OOM / 显存水位失控

先停止继续放大流量，保存每 rank 显存、KV 水位、请求长度与配置。确认是权重/graph 固定占用、KV 增长、临时 workspace 还是碎片。降级可限制 max tokens/并发、关闭高成本特性或回滚；不要只重启后宣告恢复。

### p99 突增

按 queue、TTFT、TPOT 分段，检查流量长度分布、Prefix Cache 命中、batch、CPU 调度、collective 与 GPU 时钟。若只有 canary 变差，停止扩流并保留 profiler 证据。

### 输出质量或格式回归

立即停止 canary，保存脱敏请求、模型/模板/parser revision 和采样参数。区分模型变化、tokenizer/template、约束后端与工具 parser。质量问题不能由健康探针发现。

### NCCL hang / worker 丢失

冻结拓扑与各 rank 最后日志，确认是否单 rank 先 OOM 或退出，再查 collective、NIC 和网络。需要重建副本时先从路由摘除，避免客户端请求继续进入坏组。

## 事故后

保留时间线、影响范围、检测方式、缓解与根因证据；把缺失的告警、门禁和演练补回系统。复盘重点是为何没有在更早门禁发现，而不是只记录最终修复。
