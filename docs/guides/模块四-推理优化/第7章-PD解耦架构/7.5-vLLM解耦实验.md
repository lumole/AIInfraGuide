## 跟读教程

[AWS DPD 教程](https://aws.amazon.com/cn/blogs/machine-learning/disaggregated-prefill-and-decode-for-llm-inference-on-sagemaker-hyperpod/) 提供完整部署示例，但绑定 AWS 组件。使用原生 vLLM 时，以 [Disaggregated Serving 示例](https://github.com/vllm-project/vllm/tree/main/examples/disaggregated/disaggregated_serving) 为实际操作入口，并固定 commit。

## 实验顺序

1. **统一引擎基线**：固定模型、负载、并行度，测 TTFT、TPOT、E2E 与 goodput。
2. **两池可用性**：仅验证 Prefill、KV 传输、Decode 能完成正确输出。
3. **传输成本**：按 prompt 长度分桶测 KV 大小与传输 p50/p99。
4. **容量扫描**：分别改变 Prefill/Decode worker 数和到达率。
5. **混合流量**：同时运行四类长度组合，比较统一引擎。
6. **故障注入**：传输超时、Decode worker 下线、请求取消和模型不一致。

## 固定版本

记录 vLLM commit、Connector 类型、传输库版本、CUDA/driver、GPU/NIC 拓扑、模型 revision、dtype、TP/PP、block size 和所有启动参数。该功能与接口变化较快，仅记录“latest”无法复现。

## 正确性门禁

- greedy 输出与统一基线在容许数值误差内一致；
- KV token 范围、位置编码和停止条件正确；
- 取消请求后 Prefill/Decode 两侧显存都回收；
- 重试不会重复提交 token；
- Prefill/Decode revision 或 layout 不一致时明确失败，而非静默生成错误结果。

## 性能门禁

只有在目标负载下 goodput 提升，或同等 goodput 下成本下降，才算有效。平均吞吐提高但 TPOT p99 失守，不算成功。必须把代理、排队和 KV 传输时间计入端到端指标。
