## 建议先读

[NVIDIA Inference Optimization](https://developer.nvidia.com/blog/mastering-llm-techniques-inference-optimization/) 负责建立优化全景。读完后，不要立刻选择某个引擎或量化格式，先把目标工作负载写成下面的需求表。

## 需求表

| 维度 | 要记录的内容 |
| --- | --- |
| 模型 | 架构、参数量、dense/MoE、head/KV head、revision |
| 输入 | P50/P95/P99 token、语言、图片/工具/结构化比例 |
| 输出 | P50/P95/P99 token、采样、停止条件 |
| 流量 | 到达率、并发、峰谷、会话与前缀复用 |
| SLO | TTFT、TPOT、E2E、goodput、质量阈值 |
| 资源 | GPU/CPU/内存/网络、节点边界、预算 |
| 运维 | 多租户、灰度、扩缩容、数据与安全要求 |

## 从瓶颈到候选方案

~~~mermaid
flowchart TD
    R["需求与基线"] --> MEM{"显存不足?"}
    MEM -->|是| QM["量化 / TP / PP / KV 优化"]
    MEM -->|否| LAT{"TTFT 过高?"}
    LAT -->|是| PF["Prefix Cache / Chunked Prefill / P-D"]
    LAT -->|否| TPOT{"TPOT 过高?"}
    TPOT -->|是| KD["Kernel / Spec Decode / 更高带宽"]
    TPOT -->|否| THR{"Goodput 不足?"}
    THR -->|是| DB["Continuous Batching / DP / 容量"]
    THR -->|否| KEEP["保留简单基线"]
~~~

同一症状可能有不同根因。例如 TTFT 高可能来自长 Prefill，也可能来自队列；只有后者增加副本才直接有效。先用第 9 章的指标与 profiler 定位，再选技术。

## Runtime 选择

比较 vLLM、SGLang、TensorRT-LLM 等 runtime 时，使用同一模型、精度、负载和质量门槛，检查硬件支持、功能、可观测、生态与运维成本。单个公开 benchmark 不能替代兼容性与团队能力。
