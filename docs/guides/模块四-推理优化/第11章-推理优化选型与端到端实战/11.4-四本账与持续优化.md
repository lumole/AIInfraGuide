没有现成教程把计算、显存、调度与运维放进同一维护框架。本页将前十章的结论收束为四张账；它是本站的综合模板，不是某个 runtime 的官方模型。

## 1. 计算账

记录 Prefill/Decode 的主要算子、dtype、kernel、batch/shape、FLOPs、带宽与通信。目标不是计算一个绝对精确的理论值，而是解释时间花在哪里、某优化减少了什么工作。

## 2. 显存账

分开记录权重、KV、activation、workspace、CUDA Graph 和运行时保留。量化降低权重不代表 KV 也下降；扩大 batch 后节省的空间可能重新被 KV 使用。

$$
M_{headroom}=M_{device}-M_{weights}-M_{KV}-M_{workspace}-M_{runtime}
$$

headroom 必须覆盖长度波动、临时 buffer、碎片和故障场景。

## 3. 调度账

记录 waiting/running tokens、token budget、Prefill chunk、抢占、Prefix Cache 命中、Spec acceptance、队列优先级和路由局部性。它解释为什么相同 kernel 在不同流量下得到不同 TTFT/TPOT。

## 4. 运维账

记录镜像/模型版本、依赖与许可证、启动/预热时间、扩缩容、灰度、回滚、告警、故障演练和人工维护成本。某方案吞吐高 5%，但需要专用权重、易失效的自定义 kernel 和复杂回退，可能不是生产最优。

## 6. 何时重算

模型/模板、流量分布、硬件、runtime、并行度、量化、上下文上限或 SLO 任何一项改变，都应更新受影响的账。每次发布把四张账与原始实验一起归档，避免数月后只剩一个无法解释的配置。
