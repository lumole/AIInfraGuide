没有一篇稳定的入门教程能覆盖当前 V1 Scheduler，原因是内部类与字段变化很快。本页不绑定行号，而是依据 vLLM V1 设计文档和源码整理一条可复用的阅读路径。阅读时必须固定 git commit。

## 1. Scheduler 的输入与输出

输入是 waiting/running 请求、每个请求已经计算的 token、目标 token、优先级、KV block 状态和全局 token budget。输出是一份本轮执行计划，而不是生成结果。

~~~mermaid
flowchart LR
    W["Waiting requests"] --> S["schedule()"]
    R["Running requests"] --> S
    B["Token budget"] --> S
    K["KV availability / prefix hits"] --> S
    S --> O["SchedulerOutput"]
    O --> N["request IDs + scheduled tokens"]
    O --> BT["block tables / KV actions"]
    O --> P["preempted / finished / metadata"]
~~~

读源码时先找到 SchedulerOutput 的字段，再反向查每个字段在哪里决定，比从 schedule 函数第一行顺读更容易建立结构。

## 2. Token Budget

一轮允许处理的 token 上限通常由 max_num_batched_tokens 等配置约束。对每个请求，Scheduler 比较需要计算的 token、模型长度、可用预算和 KV 空间，决定 num_scheduled_tokens。

Decode 请求通常需要少量 token，长 Prefill 可被切成 chunk。若优先保证 Decode，可降低 TPOT 抖动；若 Prefill 长期拿不到预算，TTFT 和公平性会恶化。

## 3. Waiting 与 Running

running 请求已拥有可继续执行的状态，但本轮仍可能因预算或 KV 不足无法运行；waiting 请求可能因 Prefix Cache 命中而只需计算少量后缀。队列名称不能直接等价为 GPU 上正在执行或完全未分配资源。

调度顺序还可能受 arrival time、priority、LoRA、encoder input 和结构化输出等条件影响。阅读某版本时，先列出所有会改变候选集合的分支。

## 4. KV 分配

Scheduler 请求 KVCacheManager 查找 prefix 命中，并为新增 token 分配 slot/block。分配失败意味着即使 token budget 还有剩余，也不能直接执行。

~~~mermaid
flowchart TD
    C["候选请求"] --> HIT["查 Prefix Cache 命中"]
    HIT --> NEED["计算新增 token 与所需 KV slots"]
    NEED --> ALLOC{"可分配?"}
    ALLOC -->|是| PLAN["加入 SchedulerOutput"]
    ALLOC -->|否| PRE{"允许抢占?"}
    PRE -->|是| FREE["选择请求释放/回退资源"]
    PRE -->|否| WAIT["保留到下一轮"]
~~~

## 5. 抢占与重计算

KV 不足时，调度器可能抢占某个请求，释放其部分或全部 KV；请求稍后恢复时需要重计算被丢弃的 token。抢占缓解瞬时内存压力，却增加重复计算与尾延迟。

排查频繁抢占时同时看 max_model_len、并发、max_num_seqs、token budget、KV blocks 和实际长度分布。只提高 gpu_memory_utilization 可能压缩安全余量，并不解决超额准入。

## 6. 执行后状态更新

ModelRunner 返回 sampled token 与执行状态后，EngineCore/Scheduler 更新已计算 token、停止条件、输出和 block 引用。请求完成、取消或失败时都必须释放 KV；错误的回收会表现为 KV 水位持续上升或请求读到错误前缀。

## 7. 一次最小源码实验

固定一个短 prompt、greedy、单请求和 eager 模式，在以下位置记录：

1. 请求进入 waiting 时的 token 数；
2. schedule 前后的全局 token budget；
3. prefix hit 与新分配 block；
4. SchedulerOutput 中的 scheduled tokens；
5. ModelRunner 返回 token；
6. finished 后 KV free block 数。

随后只增加一个长 Prefill，再增加一个并发 Decode，观察调度计划如何变化。不要一开始用多卡、采样、LoRA 和结构化输出。
