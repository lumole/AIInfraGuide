## 主教程

[Anyscale：Deploy Multi-LoRA Adapters on LLMs](https://docs.anyscale.com/llm/serving/multi-lora) 从共享 base model 的动机开始，逐步准备 Adapter、部署并发送请求，是本节操作主线。

## 服务端发生了什么

同一批请求可以引用不同 Adapter。引擎保留一份 base 权重，把选定 LoRA 的低秩增量加入对应线性层。高效实现会在同一 batch 中按请求映射 Adapter，而不是为每个 Adapter 复制完整模型。

~~~mermaid
flowchart LR
    R["混合请求 batch"] --> M["request -> adapter 映射"]
    B["共享 Base Model"] --> K["Batch-aware LoRA kernel"]
    A0["Adapter A"] --> K
    A1["Adapter B"] --> K
    M --> K
    K --> O["各请求输出"]
~~~

## 生产中真正要测的内容

- 同时驻留 Adapter 数与显存增长；
- Adapter 首次加载、热加载和淘汰延迟；
- 混合 Adapter batch 相对单 Adapter 的吞吐；
- 高频/低频 Adapter 路由是否造成抖动；
- base/Adapter revision、rank、target modules 是否兼容；
- 租户身份是否能访问其他租户 Adapter。

动态从任意路径加载 Adapter 会扩大供应链和权限风险。生产环境应使用审核过的注册表、校验哈希并限制可加载位置。
