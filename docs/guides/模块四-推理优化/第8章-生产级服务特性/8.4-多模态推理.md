## 主教程

[Hugging Face：Multimodal Chat Templates](https://huggingface.co/docs/transformers/main/en/chat_templating_multimodal) 用 image/video/text 消息和可运行代码解释 processor、模板与占位 token，适合先学请求如何进入模型。

## 服务端数据流

~~~mermaid
flowchart LR
    REQ["文本 + 图片/视频"] --> FETCH["获取与安全校验"]
    FETCH --> PROC["模型 Processor<br/>resize / normalize / tokenize"]
    PROC --> EMB["视觉编码与 embedding"]
    EMB --> MERGE["按占位 token 合并序列"]
    MERGE --> LLM["LLM Prefill + Decode"]
~~~

多模态请求的成本不能只用文本 token 估算。一张高分辨率图片可能产生大量视觉 token，视频还受帧数影响。入口应在下载和解码前就限制资源大小、类型、来源与超时，并在 processor 后再次检查实际 token 预算。

## 必须固定的模型契约

- model revision、processor revision 和 chat template；
- 图片尺寸、切块或动态分辨率策略；
- 每请求图片/视频数量和最大视觉 token；
- URL、base64、文件上传的允许方式；
- processor cache 的键、容量和租户隔离；
- 多模态与 TP、量化、Prefix Cache 的兼容性。

## 验收

用相同图片的不同尺寸/编码、损坏文件、超时 URL、多图顺序、纯文本和极限 token 进行测试。指标应分解下载、解码、视觉编码、LLM TTFT 和生成 TPOT，不能只报告总延迟。
