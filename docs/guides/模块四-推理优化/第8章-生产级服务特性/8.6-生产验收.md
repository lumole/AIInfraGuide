没有一篇适合初学者的现成教程能把 LLM 服务的流式、取消、错误、观测、租户隔离和灰度顺着讲完。本页依据 vLLM API、KServe 协议和 OpenTelemetry GenAI 约定整理最小验收流程。

## 1. 先定义 API 合同

在测试实现前，固定请求、响应、流式事件、usage、错误和超时的语义。兼容 OpenAI API 只表示外形相近，不代表每个字段、默认值和错误码完全一致。

| 合同 | 必须说明 |
| --- | --- |
| 输入 | 最大 prompt、最大输出、模型名、采样参数、工具/多模态限制 |
| 输出 | 文本、finish reason、usage、logprobs、tool calls |
| 流式 | 首事件、增量内容、结束事件、断线行为 |
| 错误 | 4xx/5xx、可重试性、request ID、过载响应 |
| 生命周期 | 客户端取消、服务超时、优雅停止、重试幂等 |

## 2. Happy path 只是第一层

~~~mermaid
flowchart TD
    REQ["合法请求"] --> AUTH["认证与配额"]
    AUTH --> VALID["大小、schema、模型能力校验"]
    VALID --> QUEUE["准入与排队"]
    QUEUE --> RUN["模型执行"]
    RUN --> STREAM["流式或完整响应"]
    STREAM --> USAGE["结束原因、usage、trace"]
~~~

每个箭头都应有失败用例。比如请求在队列中取消，不应再占 KV；流式响应中断，服务端应检测连接关闭并清理状态；工具参数不合法，应返回明确错误而非执行。

## 3. 最小测试矩阵

### 协议

- 非流式与流式内容一致；
- 首包、增量、结束事件顺序正确；
- usage、finish reason、模型名与 request ID 完整；
- Unicode、空输入、最大边界和未知字段处理明确。

### 生命周期

- 排队时取消、Prefill 时取消、Decode 时取消；
- 客户端断线、服务端超时、上游代理超时；
- Pod 收到终止信号后停止接新请求并完成或中止存量；
- 重试不会重复工具副作用或重复计费。

### 过载与错误

- token、并发、请求率和 body 大小超限；
- OOM 预防与真实 OOM；
- 模型加载失败、Adapter 不存在、图片下载失败；
- 错误是否可重试，是否泄漏内部路径或 prompt。

### 隔离与安全

- 租户配额、优先级、Adapter、Prefix Cache 和日志隔离；
- prompt、输出、工具参数和媒体 URL 脱敏；
- 模型与 Adapter 来源、哈希、签名和访问控制；
- 管理接口与推理接口分离。

## 4. 可观测性必须贯穿请求

同一个 request ID 应关联入口、队列、Prefill、Decode、外部工具和响应。至少观测：

- TTFT、TPOT/ITL、E2E、queue time；
- input/output tokens、KV 使用与 Prefix Cache 命中；
- 状态码、取消、超时、OOM 与重试；
- 模型/Adapter revision、实例、路由目标；
- GPU 指标和请求 trace 的时间关联。

标签不能直接放原始 prompt、用户 ID 或无限取值的 request ID 到 metrics；高基数内容进入受控 trace/log。

## 5. 灰度门禁

新版本先镜像离线回放，再小流量灰度。门禁至少包含协议兼容、任务质量、TTFT/TPOT p99、错误率、OOM、取消清理、成本/合格 token。任何一项越过阈值都自动停止扩流并保留回滚版本。

~~~mermaid
flowchart LR
    OFF["离线回放"] --> C1["1% 灰度"]
    C1 --> C10["10% 灰度"]
    C10 --> C50["50% 灰度"]
    C50 --> FULL["100%"]
    C1 -.门禁失败.-> RB["回滚"]
    C10 -.门禁失败.-> RB
    C50 -.门禁失败.-> RB
~~~

## 6. 交付证据

上线审批不应只附“测试通过”。应保留 API 合同版本、用例结果、压测 manifest、质量集版本、仪表盘、告警规则、灰度阈值、回滚命令和当班责任人。
