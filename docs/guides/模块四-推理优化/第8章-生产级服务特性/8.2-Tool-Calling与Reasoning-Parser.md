## 主教程

[Hugging Face Agents Course：What Are Tools?](https://huggingface.co/learn/agents-course/en/unit1/tools) 从工具定义、schema 和模型输出开始，并配有代码。先读它理解调用协议，再把 vLLM 看作负责模板与解析的服务层。

## 完整调用链

~~~mermaid
sequenceDiagram
    participant A as Application
    participant T as Chat template
    participant M as Model
    participant P as Tool parser
    participant X as Tool executor
    A->>T: messages + tool schemas
    T->>M: 模型特定 prompt
    M->>P: 文本 / 特殊 token
    P->>A: tool name + arguments
    A->>X: 校验后执行
    X->>A: tool result
    A->>M: 追加结果并继续生成
~~~

服务端 parser 只负责把模型输出转换成结构化调用，不能替应用执行任意函数。参数必须再按 schema 校验，工具名必须经过 allowlist，外部副作用应有认证、超时和幂等控制。

## Reasoning Parser 的位置

某些模型把 reasoning 与最终回答或工具调用放在不同特殊 token 区间。parser 依赖模型模板和输出约定；换模型、revision 或 chat template 后必须重新验证。不能因为 API 字段同名就假设不同模型兼容。

## 错误矩阵

| 现象 | 可能层级 | 处理 |
| --- | --- | --- |
| 模型直接输出 JSON 文本 | template / 模型能力 | 检查是否启用工具提示与正确模板 |
| 工具名正确、参数截断 | max tokens / stop | 调整限制并验证流式拼接 |
| parser 报格式错误 | parser 与模型不匹配 | 拒绝请求或切换已验证 parser |
| 参数合法但危险 | 应用执行层 | allowlist、权限和业务校验 |
| reasoning 泄漏到答案 | reasoning parser | 核对特殊 token 与模板 revision |
