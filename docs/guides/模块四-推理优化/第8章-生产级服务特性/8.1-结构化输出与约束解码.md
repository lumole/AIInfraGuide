## 从 schema 到 token

约束引擎先把 JSON Schema、正则或 grammar 编译成状态机。每个 Decode 步骤根据当前状态计算允许 token 集合，把其他 logits 屏蔽，再执行普通采样。

~~~mermaid
flowchart LR
    S["JSON Schema / Grammar"] --> C["编译约束状态机"]
    C --> M["当前前缀对应的合法 token mask"]
    L["模型 logits"] --> A["应用 mask"]
    M --> A
    A --> P["temperature / top-p 等采样"]
    P --> U["更新约束状态"]
    U --> M
~~~

约束保证语法，不保证字段值在业务上正确。模型仍可能生成合法但错误的日期、ID 或枚举组合，因此服务端还要做语义校验。

## 三类失败

1. **schema 不支持**：后端无法编译某些关键字或递归结构。
2. **合法 token 集为空**：tokenizer 与 grammar 状态组合无法继续。
3. **后端回退**：请求表面成功，实际没有启用约束路径。

服务应明确返回错误或回退标记，不能静默产生普通文本。

## 验收用例

- 必填、可选、嵌套、数组、枚举、转义字符和 Unicode；
- 最大长度不足、EOS 提前、流式分块与取消；
- temperature/top-p 与 grammar 同时启用；
- 多请求不同 schema、重复 schema 的编译缓存；
- schema 无法满足时的错误码和日志；
- 输出经标准 JSON parser 与业务 validator 双重验证。
