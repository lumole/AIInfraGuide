没有一篇现成入门教程能把 LLM 压测噪声、SLO 门禁、原始数据和版本 bisect 串成完整流程。本页依据 vLLM benchmark、CUDA 性能方法和 Git bisect 整理最小方案。

## 1. 建立稳定基线

固定机器、GPU 时钟与功耗策略、服务配置、模型 revision、数据集、随机种子、客户端位置和测量窗口。机器上不能同时运行其他负载。每次实验先预热，并记录温度、频率与错误。

## 2. 不用单次结果做判定

关键配置重复至少数次，保存每请求原始数据。对每个指标计算中位数与波动区间。阈值应明显大于历史噪声：

$$
\text{fail if } \Delta metric > \max(\text{absolute budget}, k\times\text{historical noise})
$$

$k$ 和 absolute budget 由历史数据与业务风险确定，不存在通用的 5%。

## 3. 门禁分层

| 层级 | 目的 | 示例 |
| --- | --- | --- |
| 微基准 | 快速发现 kernel/operator 回归 | 固定 shape GEMM/attention |
| 离线引擎 | 排除 HTTP 与路由 | 固定 prompt batch |
| 在线服务 | 检查调度和排队 | open/closed loop |
| 业务回放 | 检查真实 SLO 与成本 | 脱敏流量分布 |

微基准通过不代表在线服务通过；业务回放成本高，不适合每次小提交。应按改动风险选择层级。

## 4. 判定哪些指标

同时门禁正确性、TTFT/TPOT/E2E p95/p99、input/output throughput、goodput、峰值显存和错误率。优化吞吐但破坏质量或尾延迟，应判失败。

~~~mermaid
flowchart LR
    C["候选版本"] --> COR["正确性/质量"]
    COR --> PERF["固定负载重复实验"]
    PERF --> NOISE["与历史噪声和预算比较"]
    NOISE -->|通过| RAW["保存原始数据与 manifest"]
    NOISE -->|失败| RERUN["隔离机器后复测"]
    RERUN -->|仍失败| BIS["缩小提交范围 / bisect"]
~~~

## 5. 回归定位

先确认环境与依赖没有漂移，再区分模型、调度、CPU、通信和 kernel。选择能稳定复现且时间合理的 benchmark 作为 git bisect run 的判定脚本；结果接近噪声边界时不能自动 bisect，应先增大测量窗口。

## 6. 每次门禁的产物

- git commit 与完整依赖锁定信息；
- 服务和客户端命令；
- manifest、原始每请求数据、汇总脚本版本；
- 环境、温度、GPU 时钟与失败日志；
- 基线、候选、差值、阈值和最终判定。
