## 主教程

[ExecuTorch：How It Works](https://docs.pytorch.org/executorch/stable/intro-how-it-works.html) 用三阶段图顺着解释 export、compile/partition 和 device runtime，并给出代码路径。它就是本节主教程。

## 一条通用链路

~~~mermaid
flowchart LR
    M["PyTorch 模型"] --> E["捕获可导出的计算图"]
    E --> T["图变换 / 量化"]
    T --> P["按 backend 能力 partition"]
    P --> C["编译或 lower"]
    C --> F["设备模型文件"]
    F --> R["Runtime 加载与执行"]
~~~

模型导出把动态 Python 程序收敛为可分析图；partition 根据 backend 支持把子图交给 XNNPACK、Core ML、QNN 等；不支持的部分留给 portable/CPU kernel。每个边界都可能发生张量布局或内存搬运。

## ExecuTorch 与 ONNX Runtime 术语

| 概念 | ExecuTorch | ONNX Runtime |
| --- | --- | --- |
| 图捕获/格式 | torch.export / ExportedProgram | ONNX graph |
| 后端分配 | partitioner / delegate | Execution Provider |
| 不支持算子 | portable kernel / fallback | CPU EP / fallback |
| 设备产物 | .pte 等 | .onnx / ORT format |

术语不同，核心问题相同：哪些节点在哪个 backend 执行，边界是否引入转换，fallback 是否正确且可观测。

## 验证

每个阶段保存输入输出样例，比较 eager、导出图、lower 后和设备 runtime 的结果。动态 shape、控制流、自定义算子和 state 是常见失败点；不要等到 App 集成后才第一次比较数值。
