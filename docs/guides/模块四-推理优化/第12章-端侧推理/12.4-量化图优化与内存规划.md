## 主教程

[ExecuTorch Quantization Overview](https://docs.pytorch.org/executorch/stable/quantization-overview.html) 从量化依赖 backend 的原因讲起，并给出 PTQ/QAT 流程与代码入口。端侧量化应先确定目标 backend，再选量化方案。

## 为什么 backend 决定量化

相同 INT8/INT4 标签可能对应不同的 per-tensor/per-channel、对称性、group size、布局与算子融合。若设备 backend 不支持导出的量化算子，图会回退或插入反量化，性能可能下降。

~~~mermaid
flowchart LR
    B["目标设备与 backend"] --> Q["选择量化配置"]
    Q --> CAL["校准或 QAT"]
    CAL --> PART["按 backend partition"]
    PART --> CHECK["检查 fallback 与边界转换"]
    CHECK --> DEV["真机质量/延迟/内存"]
~~~

## 图优化

常见优化包括 constant folding、算子融合、layout 转换消除和子图 delegate。每次变换都要验证数值，并检查是否减少了 kernel/边界而非只让图节点数变少。

## 内存规划

端侧峰值不仅是模型文件大小。记录：

- 常驻权重与映射方式；
- KV Cache 随上下文的增长；
- activation 与可复用 arena；
- backend 编译/缓存与临时 workspace；
- 输入媒体解码和 App 其他内存；
- CPU/GPU/NPU 边界的 staging buffer。

长上下文测试应观察峰值与回收，确认取消、切后台和多轮会话不会泄漏。
