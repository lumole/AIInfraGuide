没有一篇现成教程把端侧 LLM 的冷/热启动、token 指标、内存、功耗和热降频连成完整协议。本页依据 ExecuTorch profiling、MLPerf Mobile/Tiny 与 Android Vitals 整理最小方案。

## 1. 固定设备状态

记录设备/SoC、RAM、OS/固件、runtime/backend、模型与量化 revision、电池状态、环境温度、充电状态、屏幕亮度和网络。关闭无关后台任务，说明是否启用性能模式。

端侧结果对固件和温度敏感；只写“某手机”不足以复现。

## 2. 分开测四段时间

- App/Runtime 初始化；
- 模型文件读取、映射与加载；
- 首次执行中的编译、kernel cache 或 NPU 准备；
- 正式 Prefill、首 token 与持续 Decode。

冷启动应从清理进程和相关缓存后的状态开始；热启动保留已定义的缓存。两者不能混在平均值里。

## 3. LLM 指标

| 指标 | 含义 |
| --- | --- |
| Load time | Runtime 到模型可执行 |
| TTFT | 请求开始到首 token |
| Prefill tokens/s | prompt 处理速度 |
| Decode tokens/s / TPOT | 持续生成速度 |
| Peak RAM | App + Runtime + 模型峰值 |
| Energy/token | 生成工作量对应能耗 |
| Thermal steady-state | 长跑后的稳定速度与温度 |

输出质量与停止条件同时验证；通过缩短输出获得更好速度不算优化。

## 4. 热稳定性长跑

~~~mermaid
flowchart LR
    COLD["冷机记录初始温度"] --> W["固定 prompt/output 循环"]
    W --> SAMPLE["每轮采样速度、温度、频率、功耗、内存"]
    SAMPLE --> STABLE{"达到稳态或规定时长?"}
    STABLE -->|否| W
    STABLE -->|是| REPORT["比较首轮、最差轮和稳态"]
~~~

至少持续到频率与速度稳定，或到业务允许的连续使用时长。报告首轮、p50、最差和稳态，而非只挑最快一次。

## 5. 多设备矩阵

选最低配置、主流配置和高端配置。每台设备重复运行，随机化候选 runtime 的测试顺序，避免后一方案总在更热状态下运行。跨设备不要只比较绝对速度，还要比较是否满足各自 SLO。

## 6. 产物

保存模型/应用构建、原始逐轮数据、设备日志、温度/频率曲线、内存峰值、质量结果和复现实验步骤。公开数字注明是否插电、是否主动散热。
